Synthesis of a 4-agent parity sweep (2026-07-21) of VibeGrid vs @gp-grid/react 0.19.0, run against origin/staging. Feeds the "gp-grid migration spec" that GH#3283 defers to. Raw sweep evidence lives in the session transcripts; every claim below carries file evidence in those reports.

## Baseline: already covered (no port work)

**Native in gp-grid:** virtualization to 500k, column resize, single-column sort (worker-based), values-filter popup with counts (*net-new — VibeGrid never had it*), fill-handle drag, pointer/touch unification (GH#2200's whole investment becomes moot), edit activation/commit/cancel lifecycle, renderer registries (cell/edit/header/valueFormatter), darkMode.

**Done in the spike** (`apps/web/src/features/entities/gp-grid-spike/`): schema→columns with label fallback, data.query rows, CommandBus-undoable edits (FocusAwareUndoRouter-compatible), field renderers (option/status badges w/ colors, date/datetime, boolean, relationship chips +N, person — *ahead of VibeGrid, which has no person renderer*, currency, object summaries), dark theme, per-cell `data-field-type`.

## False requirements — never existed in VibeGrid, do NOT scope

Column pinning/freeze, density toggle, per-column filter buttons, aggregation footer row, column auto-size (marked Planned, never shipped), person/avatar cells, discrete-page pagination (`EntityDataTable.tsx`+`PaginationControls.tsx` are dead code — zero importers).

## The port matrix (app-layer unless noted)

### Cluster 1 — Data spine (build fresh, don't port) — L
gp-grid `DataSource` over the server contract: viewport-cursor windowed refetch (overscan 50 / 50ms debounce / containment dedup), `serverTotalRows` + `hasActiveFilter`, event-bus `table_change → debounced window refetch` (exactly the GH#3283 P1 contract), clobber-then-shimmer. **Target keyset cursors + skipCount (GH#3282) from day one** — VibeGrid's adapter still uses limit/offset and never adopted them. Reusable verbatim: `filterExpressionToWherePredicate`, search-pushdown composition, whereAst mutual-exclusion contract.
⚠ Perf prerequisite: server sort/filter on JSONB fields at 200k rows is 1.4–8s (GH#2848 descoped criteria; GH#2852 index gap — status_set/single_select/user_reference/currency excluded from promoted types). The new GH#3282/#3286 indexes fix id/created_at ordering only.

### Cluster 2 — Selection + bulk actions — M/L
Cell/range/multi selection model (`selectedCells` set, anchor, shift-rect, ctrl-toggle), checkbox selection column + tri-state header, ActionsBar + RowAction filtering, delete flows (bulk AlertDialog + context-menu single), select-all math on serverTotalRows, Escape/clear, focus recovery. All app-layer; gp-grid has no selection primitive.

### Cluster 3 — Keyboard + editors — L
Keyboard nav layer (arrows/Tab/Enter/Home/End/PageUp/Down, Delete-clears via CommandBus). Editor catalog as editRenderers: date/datetime picker, multi-select/tags (port `isTagsLikeField` heuristic as-is), number/currency, boolean toggle, email/url/phone validation, relationship picker, modal long-text/rich-text (must reinvent the `vibegridx-editing-portal` outside-click exemption), inline validation display, blur-policy system, Tab-to-next-editable.

### Cluster 4 — Clipboard — L, contains the one FORK item
Copy (not confirmed in gp-grid — build TSV copy), cut, paste broadcast/auto-expand semantics, column-origin guard, and the 54KB type-coercion/validation matrix with per-cell error reporting. **gp-grid's native paste bypasses validation with no hook — the single fork-level change needed is a pre-paste interception hook** (or fragile app-side event interception). This is the strongest argument for vendoring the fork.

### Cluster 5 — Filters, search, views, columns — L
Filter operator sets per field type + FilterBuilder (nested AND/OR, 3 levels), global smart search (300ms debounce, searchable-type gating), saved views (full CRUD/visibility/pins/default/child-entity tabs — pure app rebuild), `useViewUrlSync` (**highest-risk single file: 818 lines, ≥5 documented race fixes — port test-first**), column visibility picker w/ search, column drag-reorder, device-local width persistence (note: saved views deliberately exclude widths), 3-tier column-label resolution, count chips, filter presets (localStorage).

### Cluster 6 — Renderer long tail + contracts — M/L
Email/url/phone, file/image + column-id-scoped file-link overrides (escape hatch needed beyond type-keyed registry), rating/slider, computed (f(x)/Σf/decision-table w/ violation tooltips), rollups, entity-name primary-link pattern, search-highlight. The `data-affordance`/`data-action` two-tier contract + opacity-based hover reveals. **Badge-chip navigation → EntityDrawer** (3-tier value resolution + host `onCellClick` closest() contract — L, biggest renderer-domain gap). **ARIA/testid wrapper**: aria-rowindex(+2 convention)/colindex/label format, `data-testid="cell-{rowId}-{colId}"`, `[data-surface]` undo registration, `.vibegridx-viewport.scrollToColumn` equivalent, plus a lean `__grid_debug` replacement — the `ab grid` tooling and smoke suites break wholesale without this.

### Cluster 7 — View modes — product decision required
Kanban: M — built on @dnd-kit, independent of grid internals; re-host beside gp-grid. **Gantt: L, largest single item** — fully bespoke canvas timeline (zoom, drag bars, 4 dependency types, critical path) built on VibeGrid stores; from-scratch rebuild. **Decide: does DEB actually use Gantt?** If not, this is the biggest descope win available.

### Cluster 8 — Consumers & host integrations
Cutover checklist = 7 production surfaces: EntityListView (L — owns upload dropzone modes, review overlay params, EntityDrawer, QuickCreatePanel escalation, list widgets), ChildEntitySection (M — collectionOverride/computed heights/kanban), MyWorkGrid (M), ThreadListGrid (M), GCFileBrowser (M), admin Organizations/Users (S each). Ghost-row inline creation + escalation logic (L, port `needsEscalation` rules as-is). **Store-leak fix required**: ComplianceSummaryBanner + ProjectPortfolioSummaryBanner read VibeGrid MobX internals directly — replacement needs a grid-state context (filtered rows + filter state) exposed by the new wrapper. FocusAwareUndoRouter surface registration (S). ~1/3 of the VibeGrid props API has zero production users — the replacement wrapper's API should be the used subset only.
